# 软件本体形式

本文件描述软件本体的存在形式与代码结构。软件本体指 APPs/Weave.html。

## 存在形式

APPs/Weave.html 是 Weave 主程序唯一的应用程序文件。所有 HTML、CSS、JavaScript 内联在同一文件中，不拆分为多文件结构，不引入本地文件依赖。

APPs/ 目录下另有：

- APPs/Weave.min.html — 由 test/build-min.js 生成的压缩发布版，存档格式与 localStorage 键与完整版一致
- APPs/Weave-recovery.html — 独立的恢复与设置面板；显示本地数据占用，调整 Weave 设置与键位，清空节点图，并支持节点图 JSON 导入/导出；不加载主程序，不创建节点、连线或分区 DOM。页面顶部声明当前查看的是哪一份数据——浏览器按来源隔离存储，本地文件与在线站点各存一份，页面无法跨来源读写
  - 该文件不生成压缩产物：`test/build-min.js` 只处理主程序。它同样纳入测试与在线部署工作流（部署为站点根目录的 `recovery.html`），差异仅在于没有 min 版
  - 界面语言与主程序共用 `localStorage` 的 `flow_lang` 键，词典为本文件内的独立 `I18N`，由 `test/i18n-recovery.js` 守护；新增语言需同时在本页词典与键位按钮中登记
- 其他 HTML 文件 — 独立的历史应用，与 Weave 无关

APPs/Weave.html 的浏览器兼容性说明见 ../UnsupportedBrowsers/README.md。

## 技术栈

纯 JavaScript、HTML5、CSS3、Canvas 2D、SVG、localStorage。无框架、无构建步骤。运行时唯一的外部请求是 Google Fonts 的 Inter 字体，加载失败时回退系统字体。

## 界面语言

界面支持中文与 English 两种语言，切换入口位于设置弹窗。文案以键值对形式集中定义于 M01 常量与工具的 I18N 字典。App.t(key, params) 按键取值，以 {占位符} 形式替换 params，缺失时依次回退英语、中文与键名。

节点缺省标签、描述占位提示与克隆节点后缀均通过 I18N 词典提供，随界面语言切换。

## 数据模型

状态存放于 App.canvasState：

| 字段 | 内容 |
|---|---|
| nodes | 节点数组 |
| connections | 连线数组 |
| regions | 分区数组 |
| history | 撤销历史快照数组 |

节点字段：id、label、desc、color、x、y、w、h、mirrored、collapse（可选）、life（可选，仅时序图）。

连线字段：id、from、to、label、cp1（可选）、cp2（可选）、mirrored、y（可选，仅时序图）。

分区字段：id、label、color、x、y、w、h、nodeIds、parentId。

收起记录（collapse）字段：hidden 数组，元素为 { id, dx, dy }。dx、dy 是收起瞬间各隐藏节点相对根节点的偏移，根节点移动后展开仍按根节点加偏移还原相对位置。收起闭包内任一节点被两个及以上节点连接时禁止收起。

存档另含 viewport { panX, panY, scale }，挂在 App 上，不属于 canvasState。

单位：内存与交互中的 x、y、w、h 为世界像素。序列化存档中的 x、y、w、h（节点与分区）与 collapse.dx、collapse.dy 为格单位，1 格 = GRID_PX 像素，加载时乘以 GRID_PX 还原；时序图存档的 lifeline.x/y/length、time.originY 同为格（t 的单位是时间步）。连线的 cp1、cp2 是世界像素偏移，不参与折算。可选颜色字段 node.lifeColor（时序线）与 conn.color（连线）以及线型 conn.dashed 只在设过值时写出。坐标 HUD 以格为单位显示与编辑；网格吸附在开启对齐设置时为 1 格，关闭时为 1 像素。

### 时序图存档（可读格式）

时序图导出与存档使用独立的可读形态，目标是**不看软件也能据文件画出画面**。这是该功能随首发版本发布的唯一存档形态：不设 `version`，也没有旧档兼容——开发期的内部形状（life / conn.y / dashed）不作保留。顶层带 `format: "weave-sequence"`、`mode`、`unit: "grid"`、`gridPx`、`time` 与 `messageStyle`；`nodes` / `connections` 仍是同一组数组（恢复工具按 `nodes` 与 `mode` 读写，与格式形态无关）。

| 字段 | 内容 |
|---|---|
| `nodes[].lifeline` | { x, y, length }：时序线所在列、起点（节点底边）与长度（格），直接给出绝对几何——即一条时序线最初产生的源节点；可选 `color` 为时序线自己的颜色（缺省跟随节点色） |
| `time` | { originY, step, start }：时间轴。originY 为最顶部时序线起点的绝对 Y（格），start 为该点的时间值（1），step 为每步占的格数（1） |
| `connections[].t` | 消息的时间步：`t = start + (y − originY) / step`，只认纵向；整份图整体上下移动时 originY 平移而 t 不变 |
| `connections[].line` | `"solid"` / `"dashed"`，总是写出 |
| `messageStyle` | 消息未设色时的取色规则：`colorSource: "fixed"` 配 `color`，或 `colorSource: "participant"` 跟随源参与者 |
| `viewport` | { panX, panY, scale, unit: "px" }：视口平移与缩放；平移是屏幕像素，与几何的格单位不同，故块内单独声明 |

`messageStyle` 记录导出时的取色规则（供读者还原画面）；导入不改变本机的「连线颜色跟随节点色」设置，实际显示仍按当前设置。

与渲染无关的空值不写：空 desc、空消息标签、空 regions、mirrored、cp1/cp2。节点图存档保持原有形状。

导入按 `format` 识别时序存档：`lifeline.length` 还原 life，`time` + `t` 还原 conn.y，`line` 还原 dashed，随后走同一套格→像素换算与校验。

## 导入导出

三个入口最终都汇到同一套加载路径：拖拽进画布、顶栏「导入」按钮、恢复工具（独立页面，只认 JSON）。拖拽与按钮入口按扩展名 / MIME 分流——`.png`（或 `image/*`）走图片内嵌存档读取，`.json`（或 `*json`）走文本读取，其余给出「请拖入 .json 或 .png 文件」的提示。拖拽自浏览器的图片常常没有文件名，此时 MIME 是唯一依据，因此门控同时看两者。

**导出的 PNG 自带存档**：DOM 快照与兼容重绘两条导出通道都把当前文档的存档 JSON 写进图片自身——一个 iTXt 文本块（keyword `WeaveDoc`，UTF-8、不压缩，CRC32 按 PNG 规范计算，插在 IEND 之前），内容与「导出」按钮得到的 JSON 逐字相同。图片因此**自带可再编辑的源数据**：把这张 PNG 拖回画布（或用「导入」选它）即还原整张图，含视口；时序图 PNG 还会把画布模式切回时序图。重复嵌入时同名文本块是替换而非叠加。

读取 PNG 时的失败都给出明确提示且**不动当前文档**：

| 情形 | 提示 |
|---|---|
| 图片里没有 `WeaveDoc` 文本块（含根本不是 PNG 的字节） | 该图片没有图数据（请使用本软件导出的 PNG） |
| 文本块内 JSON 坏掉 | 解析失败: {msg} |
| JSON 合法但结构非法 | 无效的存档格式（`_loadFromData` 的既有拒绝路径） |
| 只读模式 | 只读模式无法导入 |

## 画布模式与双文档

界面有两种画布模式：节点图（graph）与时序图（sequence）。切换入口是顶栏最右的模式按钮。

两个模式各持一份完全独立的文档，切换等于把 App.canvasState 换成另一份（App._modeStore 保存两份文档及各自的撤销游标与视口）。因此渲染与编辑路径都只读 canvasState，不需要按模式分叉。切换是一次存档事务：先把当前文档同步落到自己的存档键，再换指针。

两个模式共用同一套节点默认尺寸：横向 9 格（180px，奇数格）、纵向 4 格（80px）。横向取奇数格，节点横向中心才落在某一格的正中——时序图的自底边中点向下引出时序线正需要这一点。

| 项 | 节点图 | 时序图 |
|---|---|---|
| 存档键 | `flow_data` | `flow_data_seq` |
| 连接点 | 节点左右两侧（含镜像交换） | 节点底边中点，以及每条消息**源端**的时序线上（目标端不画，见下） |
| 向下延伸物 | 无 | 时序线（生命线），末端把手拖拽改长度 |
| 连线 | 贝塞尔曲线，两端箭头 | 两端同高、按避让弯曲的连线，仅目标端箭头 |
| 图专有功能 | 分区、收起、镜像、曲线控制点 | 隐藏上述入口 |
| 时序图专有功能 | 隐藏高度对齐入口 | 高度对齐 |

模式本身记在设置表（`flow_mode`），启动时回到上次使用的模式。文档类型随存档写出（顶层 `mode` 键），导入时据此落回对应模式，旧存档缺该键即节点图。

时序线是节点底边中点向下的**实线**，样式与常规连线一致（取所属节点的颜色、圆头、opacity .6、线宽 2.5×scale）。

消息的**时间高度**由 `conn.y` 决定，两端固定在该高度上，因此节点上下移动不改变消息的时间。消息**只在源端**生成连接点（白底圆 + 所属时序线的颜色描边与内点，与节点图 socket 同款），同一时序线上的同一高度只画一个；目标端不画连接点——方向由目标端的箭头指出就够了，再放一个圆点既多余又正好把箭头盖住（口径简称「公留母去」：留伸出点、去被连接点）。

### 时序线尾端固定（设置项）

默认关闭：拖动节点时**整条时序线跟着节点上下移动**，长度不变。

开启后：时序线**尾端留在原处**，节点上移就等于把时序线等量延长——消息的高度是绝对时间坐标，向上拖节点因此不会把消息甩到线外；节点也不允许被拖到自己的线尾之下（最多压到「线尾 − 最短长度 `SEQ_LIFE_MIN`」处，向下时线随之缩短）。**直接拖动节点**与**高度对齐**两条改纵向高度的路径都遵守它（共用 `_tailClampY` / `_lifeLenFromTail`）；只有节点尺寸调整例外——改高度的是节点底边，线仍以自身长度从新底边重新起算。

### 消息避让

同一时间高度上、水平投影互相重叠的消息共用端点连接点，靠**中段弯曲**分开——与节点图的平行连线是同一套做法：端点不动，只有贝塞尔控制点按 `connOffYFromIdx` 在纵向扇出（第 1 条 0，第 2 条 −14，第 3 条 +14……）。

分组用区间重叠的连通分量（`Weave.Geom.seqMsgOffsetGroups`，按 y 分层后按 x 跨度扫描），而不是"节点对"：

- A→B 与 B→A 同高 → 同组（跨度相同）；
- A→B 与 A→C 同高 → 同组（同一起点，一段包含另一段）；
- 互不相交的两对节点同高 → 不同组，互不影响。

端点因此始终停在真实的时间高度上，时间坐标保持可信。

### 消息不脱线

消息的高度是**绝对时间坐标**：节点上下移动不改变消息的时间。但它必须落在两端时序线的范围内，节点位置一变就可能被破坏，因此由 `_repairSeqMessages(allowRemove, allowExtend)` 统一收拾（返回 `{removed}`）：

| 情形 | 处理 |
|---|---|
| 上方越界：消息跑到节点底边之上 | 时序线只向下生长，接不住它。**关闭**跟随 → 移除；**开启** → 挪回线首（节点底边） |
| 下方越界：消息越过线尾 | **关闭**跟随 → 同样移除，时序线不会为了"救"一条被节点甩开的消息而变长；**开启** → 延长时序线把它接住 |

判定与"谁在移动"有关，因此 `_repairSeqMessages(allowRemove, allowExtend)` 带两个参数：

- `allowRemove=false`：手势进行中先不移除，避免拖到一半丢数据、拖回来也找不回；落定时再按策略处理。
- `allowExtend=false`：这次变化来自**节点移动**，而不是用户在摆消息本身。非跟随策略下此时不得延长时序线，否则"越界即移除"会被"顺手把线拉长"抵消掉（两个方向都必须能断，这是最初漏掉的一侧）。

**断裂预览**：不跟随策略下，越界的消息在**松手之前**就变成红色虚线，让"这一条要断了"可见。红色按消息**当前**颜色的红度分三档（`_seqBreakHex`），保证预览总比它原来更刺眼：原本不红 → `#dc2626`；已经红了 → `#991b1b`；已经红得发暗 → `#450a0a`（红到发黑，再深就是纯黑，不再往下走）。目标端箭头一并变红，避免红线上挂一个蓝箭头。同高度的**端点连接点**也一起变色，否则会出现"红线配蓝圆点"、状态读不出来——连接点是该高度上多条消息**共用**的，所以先按端点扫一遍汇总（`breakingPinHex`）：只要这个端点上**有任何一条**消息要断，圆点就跟着变红，先命中的那条决定用哪一档红（同高度共用端点，没法一条消息一种颜色）。判定与落定同一处（渲染层调 `_seqMsgBreaking`，它复用 `_repairSeqMessages` 的几何口径 `_seqBreakInfo`），因此预览与"松手后真的被移除"不会说两套话；跟随开启时越界只是"待挪回 / 待接住"，不做预览。节点尺寸调整把底边越到消息之下时同样会预览（同一条件、同一结果）。

调用点：节点拖拽（拖动中 `(false,false)`、落定 `(true,false)`）、高度对齐（`(true,false)`，有移除时弹提示）、消息创建（`(false,true)`，新建的消息本就可以把线带长）、消息拖动落定（`(true,true)`）。导入路径（`_validateLoadedData`）只按上方越界剔除：导入没有"用户正拖着节点"的语境，补线是无损的，剔除反而会静默丢掉存档里的消息。缩短时序线时另有下限：不得短于它所承载的最远消息。

### 颜色

连线与时序线各持一个可选颜色字段，都在**属性弹窗**里设置（不在右键菜单里塞一排色点）：

| 对象 | 入口 | 字段 | 缺省来源 |
|---|---|---|---|
| 连线（消息） | 右键连线 →「属性」（标签 + 颜色） | `conn.color` | 由设置项「连线颜色跟随节点色」决定：开启取源节点色，关闭用缺省线色（预设蓝） |
| 时序线 | 右键时序线 →「时序线颜色」 | `node.lifeColor` | 节点色 |
| 节点本体 | 右键节点 →「属性」（既有弹窗） | `node.color` | ——（必填，始终有值） |

弹窗里的颜色行与节点/分区属性弹窗是同一套（预设色 + 自定义色轮 + 自定义色仓）。

标签与输入框的排版也共用一份：节点详情、分区属性、连线属性三个弹窗的 `.modal-box` 带 `.modal-form` 类，字段字号、底色、边框与聚焦光晕由该类统一给出。设置弹窗与色轮弹窗的控件尺寸不同，不套用该类。

设置项「连线颜色跟随节点色」**两个模式各存一份**（键 `flow_conn_follow_graph` / `flow_conn_follow_seq`），因为两者默认值相反：节点图默认开启（连线随节点颜色，沿用既有观感），时序图默认关闭（消息用自己选到的颜色，未选过则是预设蓝）。字段只在设过值时序列化；导入时非预设色且非 `#rrggbb` 的值一律剔除。

派生关系是单向的：节点色是它自己的连接点（底边 socket，由 `_updateNodeAppearance` 一并着色）与时序线的缺省来源，所以**改节点色会同步改掉它的连接点与时序线**；时序线上的连接点属于那条时序线（`_seqLifeHex`），因此给时序线单独设色也会连带改掉它上面的连接点。

## 界面适配

响应式断点按**可用空间**取，不只看宽度：

| 断点 | 场景 | 关键处理 |
|---|---|---|
| `max-width:820px` | 平板/手机竖屏 | 顶栏换行、命中区 44px、弹窗近全屏、设置导航转横排 |
| `max-width:520px` | 手机竖屏 | 侧边栏转顶部横条、顶栏字号与内边距压缩 |
| `max-height:620px` | 任何矮视口（**含手机横屏**） | 关闭 `.modal-box` 的 `scale(1.25)`、设置弹窗改纵向自适应、顶栏压成单行可横向滚动、侧边栏恢复右侧竖排 |
| `max-height:480px` | 手机横屏 | 进一步压缩导航与行高，把高度让给画布 |
| `orientation:landscape and min-height:481px` | 平板/桌面横屏 | 设置弹窗放宽到 720px |

手机横屏的宽度常大于 820（iPhone 16 Pro Max 横屏为 956×440），只按宽度设断点会让整段移动端规则失效——弹窗按桌面尺寸渲染，再被 `scale(1.25)` 放大，在 440 高的屏幕上双向出屏。故必须有 `max-height` 分支。

`.settings-panels` 上的 `min-height:0` 不可省：设置弹窗在窄屏改为纵向排布后 `flex:1` 作用在垂直轴，而 flex 项默认 `min-height:auto` 无法收缩到内容高度以下，面板会被内容撑破容器。

viewport 声明 `viewport-fit=cover`，配合 `env(safe-area-inset-*)` 让顶栏与侧边栏避开刘海与圆角；不设 `user-scalable=no`，保留用户缩放能力。

安全区避让是无条件规则，放在 CSS 1 末尾、全部断点之前。`.header` 用 `padding-inline`、`.sidebar` 用 `padding-inline` 与 `padding-block` 写出：断点用 `padding` 简写覆盖内边距，两者同特异性，源序在后的一方获胜，无条件规则排在断点之后会让断点声明的内边距失效。

五个弹窗遮罩的 `z-index` 一律显式写出（`#modal` 300、`#cpModal` 400、`#settingsModal` 350、`#regionModal` 360、`#connModal` 365）。缺省为 `auto` 时遮罩会排在顶栏（`z-index:100`）之下，顶栏覆盖的一条区域内点遮罩不关闭、也点不到弹窗顶部内容。

守护见 test/mobile-layout-test.js。

## 渲染结构

画布元素自 #canvasStage 起嵌套，缩放层位于平移层内部，scale 叠加在 translate 之上：

```
#canvasStage (.canvas)
├─ canvas#gridCvs          网格线，绘制于屏幕像素空间
├─ #canvasWorld            transform: translate(panX, panY)
│  ├─ svg#regionsSvg        分区矩形
│  ├─ #regionLabels         分区标签
```

## 输入手势

鼠标手势与触控手势并存，互不干扰：画布在触控指针按下起即 preventDefault，浏览器不再合成鼠标事件，因此不存在双重触发。

触控手势层实现于 Pointer Events（`pointerdown/pointermove/pointerup/pointercancel`），`pointerType === 'mouse'` 一律放行给既有鼠标处理器，只有 touch/pen 进入指针层。MDN 规定混合鼠标/触控输入应使用 Pointer Events。

触控不另写一套拖拽实现。既有手势代码只读事件上的 clientX/clientY 与修饰键，对事件类型无假设，故有两个转换点：

- `_bindDragListeners` 同时绑定 mousemove/mouseup 与 pointermove/pointerup/pointercancel（指针事件归一为同构的 `{clientX, clientY}`，且过滤 `pointerType === 'mouse'`，否则真实鼠标的同一次物理移动会被应用两遍）——节点拖拽、连接点建线、调整手柄、分区移动因此在触控下原样工作
- `App._touchFire` 补发同构的合成鼠标事件——手势起手补发 mousedown，点击补发 mousedown → mouseup → click，双击追加 dblclick，长按补发 contextmenu

单指一次按压的三态分界共用同一次 pointerdown：位移超过 `TOUCH_DRAG_SLOP` → 真实拖拽；按住 `TOUCH_LONGPRESS_MS` 不动 → 长按弹菜单；抬手且前两者皆未发生 → 点击，窗口内的第二次为双击。双指为捏合缩放并平移。按下即 `setPointerCapture`，拖拽在手指滑出画布后不中断。

触控补齐的操作（触屏无修饰键、无右键、无滚轮、无物理键盘）：

| 桌面操作 | 触控入口 |
|---|---|
| 右键菜单 | 长按节点 / 连线 / 分区；长按空白弹画布菜单（粘贴、全选、框选模式、适应视图） |
| Ctrl + 单击（多选） | 侧边栏「多选模式」开关，开启后点按节点累加/移出选中 |
| Alt + 单击（关联高亮） | 节点菜单「高亮关联节点」 |
| Shift + 拖拽（框选） | 侧边栏「框选」模式开关，开启后单指拖拽空白 |
| 高度对齐 | 侧边栏「高度对齐」开关（无修饰键依赖，桌面与触控同一入口） |
| 滚轮（缩放） | 双指捏合 |
| Ctrl + 滚轮（换色） | 顶栏「颜色」按钮 |
| 切换画布模式 | 顶栏最右的模式按钮（无键盘/修饰键依赖，桌面与触控同一入口） |

仅空白画布一路（平移、框选、分区预览，驱动位于 M13 尾部的 document mousemove）需由 `_ptrMove` 补发 mousemove；其余手势各自已接管 pointermove，补发会造成重复位移。

## 高度对齐工具

侧边栏开关（`#btnAlignNodes`），把多个节点拉到同一纵向高度。仅时序图模式提供：节点图模式下侧边栏入口隐藏，键位路径同样拒绝开启。

| 项 | 行为 |
|---|---|
| 默认模式 | 没有选中节点时，操作把**全部**节点拉到该高度 |
| 选定模式 | 已选中部分节点时，只拉选中的那些 |
| 什么时候算一次对齐 | **按住不动达 `ALIGN_HOLD_MS`（500ms）、或移动超过 `ALIGN_DRAG_SLOP`（10px）**才开始；两个阈值都取与触控"点击/拖拽/长按"分界相同的常量。参考线出现就表示这一下会对齐（它同时是提示），因此不会出现"按下去才发现搞错了"的情况 |
| 常规单击 | 上面两条都不满足就松手 = **常规空白单击**：不对齐，走画布空白单击的既有语义（取消选中）。否则选中之后只剩 Ctrl+单击一条退路，选中会变成"无法撤回"的状态 |
| 判定机制 | **松手才落定**：开始之后只记高度、移动继续调，松开才移动节点 |
| 对齐基准 | 节点的**左上角纵向判定点**（`node.y`）落在参考线上——**不是纵向中心** |
| 参考线与落点 | 参考线吸附并画在**格子划分线**上（`y = k·GRID`）。它把要对齐到的格子定义为自己**下方那一格**：该格的上边界就是这条线，所以节点左上角落在线上，正好落进它下方的格子里。高度不一的节点同样如此（都对齐左上角） |
| 吸附 | 参考线高度按「对齐节点」设置吸附，与节点拖拽的落点同一规则 |
| 退出 | 再点一次按钮，或按 Escape |

起手点是画布空白处（`onCanvasMouseDown` 分流，与分区创建同级）；落在节点上的按下仍走节点拖拽。手势经 `_bindDragListeners`，触控端由 `_touchBeginDrag` 在位移越过阈值后补发的 mousedown 启动，因此**触控靠拖动来对齐**（触控的原地长按另有其义：弹画布菜单，见 M08 `_touchLongPress`）。

开启「时序线尾端固定」时对齐同样让线尾留在原处、并把节点夹在自己的线尾之上。落定后会整理时序图不变量：补足不再覆盖消息的时序线，撑不住的消息按同一规则移除（`_repairSeqMessages`，有移除时额外弹提示）。

时序图模式的两条手势（M08）遵循同一套约定，因此触控自动生效：

- 拖拽时序线末端把手改长度：`startSeqLifeDrag`。
- 从时序线拖出消息：`startSeqMsgDrag`，**拖动过程中上下移动同时决定消息高度**（高度连续跟随光标、夹在源时序线范围内），松手用 `_findSeqLifeHit` 按水平距离判定落点，命中另一条时序线则经 `_createSeqMessage` 建线。

两者的起手都要 `stopPropagation`：`#seqSvg` 是 `#canvasStage` 的子层，不拦下按下事件就会冒泡进画布空白手势，把改长度 / 拉消息变成平移画布。松手后浏览器补发的画布 click 由 `_swallowNextCanvasClick()` 吞掉（一次性守卫，窗口 `DRAG_CLICK_GUARD_MS`），保住刚建立的选中；节点拖拽、消息拖拽与高度对齐落定后同样调用它。

长按菜单有两处配套处理：菜单下移避开指尖；`_ctxGuardUntil` 窗口内"没有前置 pointerdown"的 click 视为浏览器补发并拦下——用户点菜单项必然先有 pointerdown，不受影响。

### 消息的「调整位置」（右键菜单）

时序图的连线与连接点都可在右键菜单里选「调整位置」进入移动模式（`_seqMoveState`），随后上下拖动即可改高度：

| 对象 | 拖动效果 |
|---|---|
| 消息连线（`kind:'conn'`） | 只改这一条的高度，两端端点由几何自然跟随（目标端只有箭头）；连线上叠加高亮并在中点画一个拖拽把手 |
| 消息连线（多选整组） | 右键命中那一根若在**多选集**内且不止一根，整组一起进入移动模式（组内每条都高亮、都有把手）；拖动是一次整体平移，各条的相对高度差保持不变 |
| 连接点（`kind:'pin'`） | 改该点（身份 = 节点 + 基础高度，见 `_seqPinConns`）上**所有**消息的高度，因此它们的另一端也一起移动；整组成员在进入时冻结并整组高亮（连线 + 中点把手），不会出现"看不见的线跟着动"。圆点只画在源端，但成员判定与圆点画在哪无关：一个点上只要有消息伸出去就有圆点可抓 |

参与移动的那一组在**进入移动模式时冻结**（`_seqMoveState.ids`），与高亮一致，不受其间选择变化影响。

时序图的可拖动把手（时序线末端、消息中点）统一为一个样式：**白底小圆角正方形 + accent 描边**，几何与描边都按 scale 预乘，两处共用同一份实现 `_seqHandleEl` 与同一条 CSS 规则（`.seq-drag-handle`），不各写一套。

连线移动模式的拖动面是整个命中路径（不只是把手）；连接点画在时序线之上，因此不在移动模式时按下它与按下时序线同义（拉出一条新消息），否则会吃掉时序线的命中而退化成平移画布。目标端没有连接点，那里按下就是拉新消息。Escape 或空白单击退出移动模式，撤销 / 重做 / 切模式会一并收掉。

### 线型

连线带 `dashed` 字段，右键菜单按当前状态给出「改为虚线」/「改为实线」。虚线间隔与描边宽度同规则按缩放预乘（SVG 内坐标已预乘 scale），箭头不受线型影响、始终实心；PNG 导出两条通道（DOM 快照与 Canvas 回退）同样处理。菜单项当前只在时序图模式下出现。

### 动画与过渡

拖动与吸附统一按"连续跟随 + 落定动画"处理，与节点拖拽同一套约定：

- 拖动中数值**连续跟随光标、不吸附**（因此不会逐格跳变、即"无级调节"）：节点尺寸（右键菜单「调整节点大小」的四个角手柄）、时序线长度、消息创建高度、连线 / 连接点移动都是如此。
- 松手时经 `_animateSnapTo` 平滑落到吸附值。它是 M07 的**通用过冲吸附动画**：曲线复用节点吸附的 `Weave.Geom.snapFrames`（100ms 线性 + 50ms 过冲尾段），并接入 M07 既有的帧流引擎（240Hz 数据流 + rAF 渲染流，由 `_ensureSnapEngine` 起流），因此与节点 / 分区的吸附动画共用同一套调度，不再各写一套 rAF 循环。参数是等长数组（1 元 = 时序线长度 / 消息高度，2 元 = 节点宽高），`apply(vals)` 只写数据（渲染流每帧都会刷新一次连线），`commit()` 写 DOM，`done()` 写历史与存档；末帧恰好落在目标上。
- 节点尺寸调整的每一帧都经 `_resizeNodeTo` 重算，**对面角保持不动**（`nw`/`sw` 改 x、`nw`/`ne` 改 y），拖动中与动画中一致。
- 是否吸附由设置项决定：节点尺寸看「节点大小对齐」（`_snapSize`，关闭后只收敛到整像素）、消息高度看「连线对齐」（`_snapConn`）、时序线长度始终逐格吸附。
- 时序图的可拖动把手（时序线末端、消息中点）与消息连接点**不做任何悬停变色 / 半透明**，始终是实心白底：它们是拖拽的着力点，悬停反馈只会造成误解。时序线末端把手是**编辑态专有**：只读态屏上与 PNG 导出（两条通道）都不画，导出的因此始终等于当前所见。

### 侧边栏图标

右侧边栏的开关图标统一为 24×24 / `stroke-width:2` 的线性风格，每个图标只用 2–3 个形状，保证 16px（窄屏 20px）下仍能辨认；颜色只由 `.sidebar-btn` 的 `color` 给，图标本身不写颜色（`currentColor`）。设计取各设计软件通行的隐喻，不做微缩画：

| 按钮 | 图形 | 隐喻 |
|---|---|---|
| 导出为图片 | 相框 + 山与太阳 | 图片文件 |
| 只读模式 | 挂锁 | 锁定不可改 |
| 多选模式 | 打勾的方块 + 右下角的加号 | 勾选一个还能再加（点按累加选中） |
| 画框分区 | 带标题页签的框 + 框内一个方块 | 有名有内容的容器——分区在画布上就是这个样子 |
| 框选模式 | 虚线选框 + 指针 | 拖拽拉出的临时选框 |
| 高度对齐 | 两个方块的上边缘贴在同一条参考线上（一高一矮） | align top：把高度不同的东西拉齐到一条线 |
| 设置 | 齿轮 | 通用约定 |

虚线只用在"临时 / 待画"的语义上（框选选框、高度对齐的参考线），实线一律表示画布上真实存在的对象（分区）——两条画布模式开关因此不会看混。

### 设置界面（两套）

常规页顶部一行标题写明当前是哪一套（「节点图设置」/「时序图设置」），并按当前画布模式只显示相关项（`_applySettingsModeFilter`，切模式与打开弹窗时都会刷新）：

| 画布模式 | 显示的对齐项 |
|---|---|
| 节点图 | 对齐节点、节点大小对齐、分区位置对齐网格、分区大小对齐网格、连线颜色跟随节点色（默认开） |
| 时序图 | 对齐节点、节点大小对齐、连线对齐网格、消息跟随节点、连线颜色跟随节点色（默认关）、时序线尾端固定（默认关） |

语言等全局项两者都显示；「重置对齐设置」**只复位当前这套界面里看得见的对齐项**（`_settingRowInMode` 按 HTML 的 `data-modes` 判定，因此模式归属只有一份事实来源）：在节点图里点它不会顺手改掉只在时序图里显示的「连线对齐」，反之亦然。对齐设置是一组共享的值；跟在 `_snapToggleDefs` 之后的非对齐开关走 `_miscToggleDefs`，不参与该复位。**隔离只在界面层**：每一项的值仍是同一份，切模式不会看到两个不同的值。打开弹窗与切模式时会把复选框勾选同步为 App 字段的当前值（`_applySettingsModeFilter` 末尾），使程序化改过的值不会让界面停在旧勾选。

各对齐设置共 5 项，接线映射见 `App._snapToggleDefs`，设置弹窗与恢复工具都有对应开关。
